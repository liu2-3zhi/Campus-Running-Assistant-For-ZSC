# 数据库优先存储设计

日期：2026-11-24。状态：依据用户确认的关系化方向实施，并加入指定数据副本迁移测试。

## 目标与授权边界

- 冻结 JSON/INI 文件运行后端；正常运行仅允许 SQLite 或 MySQL/MariaDB，不允许数据库故障后回退旧文件。旧文件及旧 app_documents 结构仅作为显式迁移输入。
- 本地开发和测试默认创建 data/application.sqlite3。检测到尚未迁移的旧业务数据时拒绝悄悄启动空库。Docker MySQL 配置直接写 environment，不依赖 env 文件，也不内置 MySQL 服务。仓库示例只含占位值。
- 用户明确要求迁移测试前清空指定 MySQL 数据库。执行顺序必须是：只读盘点、完整备份与校验、本地实现及验证、清理指定库内对象、迁移副本、独立复核；不删除数据库和账号，不修改源副本。实际连接凭据不写入代码、文档、测试或提交。
- 日志位置、文件名、归档和挂载保持不变；图片、头像、缓存、上传、证书等非结构化资源继续保留在原路径。

## 当前问题

当前 business_storage.py 的两张表保存文档字节及就绪标志；storage_io.py 通过目录、文件存在性、修改时间等接口模拟磁盘。业务实体和索引藏在 JSON/INI 内，多个领域更新没有共同事务。仅复制为多张同结构 BLOB 表不能解决关系、约束和查询问题。

auth_system.py 存在组归属双重来源；学校账号 owner JSON 与全局 INI 分别保存凭据/UA 和统计；注册 Token 是每用户一个而非每会话一个。订单、退款和账单关系目前靠嵌套列表表示；背景绑定每次改写整份状态。迁移必须保持这些语义，而非按文件名猜测归属。

## 架构

数据库引擎、版本与事务集中在 persistence 包，使用 SQLAlchemy Core 支持 SQLite 和 MySQL。每个操作使用独立连接，显式事务内复用当前执行上下文连接；异常回滚，禁止跨线程共享 Session。SQLite 启用外键、WAL 和有界等待。

按身份、会话、任务、支付、内容、配置及背景领域建立实体表。可筛选和关联的字段为独立列；动态任务、外部服务扩展和历史归档保留 JSON。原始业务正文不得继续作为一张通用 BLOB 表的运行权威来源。

旧业务调用可暂时经 storage_io 的局部接口进入关系化存储转换层，但该层只访问数据库实体，不保留可选文件运行后端。适配接口是兼容边界，不是另一套权威存储。文档定位/版本元数据用于兼容路径与并发检测，不作为业务表替代品。

## 领域约束

1. 用户、权限组、组权限、用户组和用户差分权限分离；用户名区分大小写。权限归属冲突必须报告，不默认扩大权限。
2. 全局 school_accounts 保存学号字符串、统计、共享参数；user_school_accounts 按 owner + 学校账号唯一，保存密码和独立 UA。相同学号绑定给不同系统用户时不得共享 UA。
3. sessions 与账号级会话状态分离；用户 Token 仍为每用户一个，游客 Token 才为每 UUID 一个。不得用会话级联删除改变用户 Token 生命周期。
4. payment_orders、billing_records、payment_order_bills、payment_refunds 分离；金额用整数分，迁移使用 Decimal 检查精度；账单属于学校账号，不随创建用户级联删除。
5. 后台任务的执行对象、线程、停止事件和临时失败摘要仍在内存；持久任务按 session/execution/version 防止旧批次覆盖新批次。
6. 留言与提醒逐条存储；用户删除不级联丢失历史展示快照。拒绝/删除留言的既有日志留在原 logs。
7. 背景 assignment、bundle 和身份/游客绑定分离；数据库只保存图片引用，图片删除继续遵守现有共享文件锁。
8. 删除账号归档按删除批次唯一，保留历史身份快照；不能因删除活跃用户级联移除归档。
9. 应用配置、信任 IP 等结构化设置入库；容器启动 SSL 配置读取同步调整。只把数据库连接与极少量启动环境变量作为部署引导。

## 无损兼容和迁移

实体核心列为唯一权威值；剩余动态字段保留在扩展 JSON，字段存在性和旧格式信息仅用于兼容重建。迁移后的源文档数量不等于实体行数，须逐来源映射核对语义、类型、金额、UA、引用及行数。

迁移支持旧文件副本、v1 文档数据库到新结构；源保持只读。预检所有文档后再写入；源摘要、映射、版本、状态和校验结果可追踪。重复迁移幂等，冲突不得静默覆盖。失败不标记就绪。

未知字段、空值、字符串 NA、旧 scope 的缺失/空/NULL/非法情况必须区分保留；不能通过清零、默认 owner 或修正密码格式掩盖不一致。旧索引用于交叉核验，SQL 索引从实体数据建立。

## 验收

- 默认临时 SQLite 运行所有新存储契约、约束、回滚、并发、关系化重建测试。
- MySQL 使用用户明确指定的测试库；清空前备份全部对象及数据并重新读取校验，源副本全部文件做内容/大小/mtime 基线。
- 真实副本迁移到独立 SQLite，再迁入清理后的 MySQL；核验来源、实体、金额、UA、摘要和引用，数据库 ready 状态只在全部通过后设置。
- 运行现有 Python、JavaScript 回归，重点保留多账号 UA、会话销毁、管理员查看态、Token 和支付幂等行为。
- 当前仍为单应用实例，不把进程内执行锁宣称为分布式锁。
