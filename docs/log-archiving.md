# 日志轮转与启动归档

主日志、WARNING、ERROR 分别顺序编号。每类保留最近 `Logging.log_backup_count` 份编号原文（默认 10），更早文件归档成功后才删除。不新增 WebUI 设置，现有单文件大小、归档容量和目录配置继续生效。

例如第 11 份历史生成后，`zx-slm-tool-01.log` 进入 ZIP，原文保留 `-02` 至 `-11`。三个当前日志始终继续写入，运行中的归档不处理背景目录。

## 归档事务

`log_archiving.py` 统一执行以下顺序：

1. 保存带唯一批次标识的 `.batch-*.json` 清单，记录源路径、大小、修改时间和 SHA-256。
2. 写临时 ZIP，关闭后检查成员列表、CRC 和内容摘要，并再次核对源文件。
3. 无覆盖发布正式 ZIP，再按清单核对并删除已备份源文件。
4. 全部清理完成后删除清单，执行容量清理。

压缩、校验或发布失败会保留原文，允许编号历史暂时超过保留数量。归档重试与轮转重试独立，按 2、4、8、16、32、60 秒退避；后续日志成功写入时也会检查重试时间，不要求再次轮转。当前记录写入失败时不开始归档。

ZIP 已发布而源文件未删完时，恢复只校验已有 ZIP 并继续清理，不重新打包。路径被新内容复用时保留新文件，退出旧批次的删除义务。未发布且源内容已改变的过期批次会保留原文并退出，后续尝试重新备份当前内容。不要手动删除尚未完成批次的清单或 ZIP。

ZIP 总容量超过 `Logging.archive_max_size_mb` 后从最旧开始清理，始终保留最新一份和仍在清理源文件的批次。最新 ZIP 单独超过上限时保留并输出提示。容量为 `0` 时不限制。

## 启动与背景重置

单实例锁成功后、创建日志处理器和启动背景预热/Web 服务前，分别执行日志和背景批次。日志候选只包括三个当前日志及其数字编号历史，兼容旧的一位编号；其它文件不参与。

背景批次备份整个 `random_background_image`，包括空文件、子目录、状态和旧版索引。校验通过后将旧目录切换到批次暂存目录，建立空目录、空状态和空索引，清空内存随机选择记录。用户、游客、旧版会话的背景绑定全部重置，账号和会话中的主题偏好不受影响；旧 ZIP 不自动恢复。

背景归档失败时保留尚未备份的数据和绑定。暂存目录删除失败时保留清单，下次启动继续清理；运行期间不恢复或清理启动批次。日志与背景失败相互隔离，重复初始化日志不再清空背景。

运行时缓存容量清理仅处理缓存图片，保护状态、索引、临时文件和仍被新旧绑定引用的图片。绑定元数据读取失败时跳过删除；所有图片都受保护时允许暂时超限并提示。选图、绑定、索引和删除共用锁，网络请求在锁外执行，下载完成后原子发布。预热没有图片时返回兼容的空数据，不持久化全空绑定；后续登录、游客和 UUID 初始化可重试。

## 验证

专项测试包括 `tests/test_log_rotation_ordering.py`、`tests/test_log_rotation_resilience.py`、`tests/test_log_archiving.py`、`tests/test_log_archiving_integration.py`、`tests/test_background_cache_safety.py`、`tests/test_background_empty_bindings.py`，以及背景绑定、身份绑定和每日重启回归。

所有归档和重置测试使用临时目录。曾被旧版本直接删除且没有备份的历史日志无法由此次改造恢复。
