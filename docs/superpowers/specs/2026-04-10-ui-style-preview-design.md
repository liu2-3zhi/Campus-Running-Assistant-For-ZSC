# UI 静态风格稿设计

- 日期：2026-04-10
- 主题：前台登录页与后台配置页的静态风格稿
- 状态：待用户评审

## 1. 背景

当前项目已经存在一套偏现代化的浅色后台样式，尤其是 `admin-config-form` 及其 `createInput(...)` 生成的配置项，呈现出以下特征：

- 浅色基调
- 卡片化表单
- 蓝色系点缀
- 轻渐变、轻阴影
- 局部玻璃感

但这些特征主要集中在局部区域，尚未扩展成“前台 + 后台”统一、可选择的整体视觉方向。

本次工作不直接改造现有业务页面，而是先制作一批纯静态 HTML 风格稿，帮助用户快速选择 UI 方向，再决定如何映射回真实页面。

## 2. 目标

输出 3 套完全不同方向的静态风格稿，用于视觉选型。

每套风格稿都包含：

1. 前台登录页
2. 后台配置页
3. 桌面端展示
4. 移动端展示

## 3. 设计原则

1. **只做风格验证，不接入现有逻辑**
   - 不接入 `scripts/main.new.js`
   - 不调用真实接口
   - 不依赖真实配置数据

2. **页面只复刻代表性内容**
   - 目标是帮助选择视觉方向，不是复刻整个系统
   - 只保留登录页与配置页中最能体现风格的关键结构

3. **风格差异必须足够明显**
   - 不能只是同一套设计换颜色
   - 三套方案需要在气质、层次、背景、卡片、按钮和信息密度上拉开差异

4. **保留后续落地空间**
   - 风格稿虽然是静态页面，但需考虑未来迁移到真实页面时的可实现性
   - 后台配置页需要能够映射到 `admin-config-form` 这种分组 + 字段卡片结构

## 4. 风格方案

### 4.1 方案 A：极简专业风

定位：偏现代 SaaS / 管理后台风格，强调干净、稳定、清晰。

视觉特征：

- 大面积留白
- 弱渐变或纯色背景
- 明确的区块边界
- 较克制的阴影与圆角
- 重点通过排版、间距、层级建立秩序

适用判断：

- 如果后续希望落地风险最低
- 如果希望后台长期使用耐看、不容易审美疲劳

### 4.2 方案 B：玻璃科技风

定位：更强产品感与科技感，强调辨识度。

视觉特征：

- 半透明卡片
- 模糊背景
- 更明显的渐变、光晕、透明层次
- 按钮和重要区域有更强聚焦效果
- 前台登录页更有“展示型产品首页”气质

适用判断：

- 如果希望整体风格更有记忆点
- 如果希望前台视觉吸引力更强

风险：

- 需要控制装饰强度，避免影响可读性

### 4.3 方案 C：品牌化柔和风

定位：更亲和、柔和、易长期使用的品牌型界面。

视觉特征：

- 柔和渐变背景
- 更圆润的卡片与按钮
- 更明显的品牌色层次
- 提示区、分组区、表单区更具亲和感
- 后台看起来不像“纯工具台”，而更像有统一品牌语言的产品后台

适用判断：

- 如果希望前后台统一成更完整的产品气质
- 如果希望避免过冷、过硬的后台观感

## 5. 页面范围

### 5.1 前台登录页

静态稿中应体现以下元素：

- 页面背景
- 品牌标题 / 副标题
- 登录卡片容器
- 用户名 / 密码输入框
- 主按钮 / 次按钮
- 辅助说明文案
- 桌面端与移动端下的层级变化

### 5.2 后台配置页

静态稿中应体现以下元素：

- 顶部标题栏
- 操作按钮（如刷新、保存）
- 风险提示区
- 配置分组标题
- 多个配置卡片
- 输入框、下拉框、说明文案
- 桌面端与移动端下的布局变化

后台配置页的结构需要与当前 `admin-config-form` 的“分组标题 + 字段卡片”模式保持语义一致，但视觉表达允许完全重做。

## 6. 响应式展示方式

为了便于用户直接比较，每个静态稿页面都同时展示：

- 一块桌面端预览区域
- 一块移动端预览区域

即：

- 登录页 HTML：同页展示桌面登录稿 + 移动登录稿
- 配置页 HTML：同页展示桌面配置稿 + 移动配置稿

这样用户打开单个 HTML 文件即可同时看到该风格下的两端效果，而不需要切换浏览器尺寸。

## 7. 文件组织

本次静态稿建议放在独立目录中，与业务文件隔离。

建议路径：

- `ui-previews/style-a-login.html`
- `ui-previews/style-a-admin.html`
- `ui-previews/style-b-login.html`
- `ui-previews/style-b-admin.html`
- `ui-previews/style-c-login.html`
- `ui-previews/style-c-admin.html`

说明：

- 每个文件独立可打开
- 以静态展示为目标
- 不覆盖现有页面

## 8. 实现约束

1. 页面为纯静态 HTML
2. 样式可使用内联 `<style>` 或页面内自包含 CSS
3. 不要求真实交互，只需有基本 hover / focus 展示即可
4. 不引入现有业务脚本
5. 不修改当前线上页面入口

## 9. 验收标准

完成后应满足：

1. 共输出 6 个静态 HTML 文件
2. 三套风格在视觉气质上明显不同
3. 每套都包含前台登录页与后台配置页
4. 每个 HTML 文件内都能同时看到桌面端与移动端展示
5. 后台配置页能明显映射到当前 `admin-config-form` 的使用场景
6. 用户可以基于这些稿件直接选择下一步落地方向

## 10. 非目标

本阶段不包括：

- 改造真实业务 UI
- 接入真实配置项数据
- 接入 API 或现有 JS 逻辑
- 统一整个项目所有页面
- 做成高保真可交互原型系统
