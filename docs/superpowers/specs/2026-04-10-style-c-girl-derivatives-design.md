# Style C 少女向衍生风格稿设计

- 日期：2026-04-10
- 主题：在 Style C（品牌化柔和风）基础上继续扩展少女向静态风格稿
- 状态：待用户评审

## 1. 背景

上一轮已经产出 3 套静态风格稿，其中 Style C 的定位是“品牌化柔和风”，核心特征为：

- 柔和渐变背景
- 更圆润的卡片与按钮
- 粉 / 紫 / 蓝的品牌层次
- 亲和、可长期使用的产品气质
- 前后台统一为同一套品牌语言

用户对 Style C 的整体方向更偏好，但认为当前版本还不够满意，希望在这个方向上继续衍生，而不是重新回到极简专业风或玻璃科技风。

本轮衍生的新增要求是：

1. 明确往“二次元、粉色少女风”发展
2. 仍要保留可用于真实产品界面的可落地性
3. 必须同时考虑深色模式，而不是只做亮色版
4. 后台配置页也要明显拥有同样的少女向气质，而不是只在前台强化风格

## 2. 目标

在现有 Style C 基础上，再扩展 3 套同宗但分支明显的少女向静态预览风格，供用户继续筛选。

每套风格都包含：

1. 前台登录页
2. 后台配置页
3. 同页展示桌面端
4. 同页展示移动端
5. 同页展示亮色与深色模式的完整风格表达

## 3. 设计原则

### 3.1 延续 Style C，而不是推翻重做

新的三套方案需要让人一眼看出它们是 Style C 的衍生，而不是新的大类。

应继续保留：

- 柔和品牌感
- 圆角和卡片体系
- 品牌化表单体验
- 前后台统一气质

但会在配色、装饰语言、情绪浓度、深色模式表现上进一步拉开差异。

### 3.2 少女风要成立，但不能牺牲可用性

页面可以明显偏甜美梦幻、二次元少女向，但仍需保证：

- 表单识别清晰
- 按钮层级清晰
- 配置项结构清晰
- 提示信息与风险信息可快速阅读

后台配置页不能只像插画页或活动页，仍需保留“可操作的系统配置界面”语义。

### 3.3 深色模式必须是设计的一部分

深色模式不是把浅色背景简单反相，而是要形成完整成立的“夜樱梦幻版”体验。

深色模式应具备：

- 柔和但明显的粉紫发光层次
- 深底下依然清晰的输入框与配置卡片
- 与亮色版同一世界观，但情绪更像夜晚樱花

### 3.4 后台也要保留明显风格性

后台配置页本轮不走“收敛专业版”，而是与前台一样保持较强风格统一。

也就是说：

- 管理台要有明显少女向风格
- 但必须继续保留标题栏、提示区、分组标题、字段卡片、输入项等后台结构
- `admin-config-form` 的“分组 + 字段卡片”语义仍然是映射基础

## 4. 三套衍生方案

### 4.1 方案 C1：樱雾奶霜风

定位：最柔和、最甜美、最耐看的一套，重点做“奶油粉樱花产品感”。

视觉关键词：

- 樱花粉
- 奶油白
- 淡莓紫
- 雾面高光
- 珍珠感边框
- 轻微糖霜质感

亮色模式特征：

- 大面积奶白与粉樱渐变背景
- 卡片像奶霜甜点盒，边界柔和
- 按钮与标签带轻微珠光感
- 表单边框更细、更轻、更柔亮

深色模式特征：

- 夜樱雾紫背景
- 低对比深莓紫 / 暗樱粉渐变
- 发光较轻，重点在雾化和柔光，不做强烈霓虹
- 适合长时间看，不强调冲击感

适用判断：

- 想要最稳定、最耐看的少女向版本
- 想让风格甜美但不过分花哨

### 4.2 方案 C2：甜心饰品风

定位：二次元符号最明确的一套，强调“少女饰品化 UI”。

视觉关键词：

- 蝴蝶结
- 星星
- 徽章
- 贴纸边框
- 糖果按钮
- 收集卡片感

亮色模式特征：

- 局部加入装饰型符号元素
- 输入框、标签、按钮像贴纸或饰品卡片
- 分组标题更像“徽章栏”或“收藏分区”
- 信息层级更活泼，视觉记忆点更强

深色模式特征：

- 莓果粉紫 + 夜空莓蓝组合
- 小装饰高光更明显
- 深色下保留星点、徽章、贴纸反差
- 更接近二次元风格产品界面

适用判断：

- 想要更强的二次元辨识度
- 想测试“符号型少女风”能否接受

风险：

- 如果控制不好，容易显得过杂
- 后台页尤其要注意不要因装饰太多而影响配置操作感

### 4.3 方案 C3：夜樱双生风

定位：最强调亮暗双主题完整表达的一套。

视觉关键词：

- 白天樱梦
- 夜晚樱影
- 双生主题
- 月夜花雾
- 梦境切换感

亮色模式特征：

- 亮色页是甜美、梦幻、轻盈的樱粉产品界面
- 版面更通透、呼吸感更强
- 文案区和品牌区有更明确的“梦境入口”气质

深色模式特征：

- 深色版不是附属，而是完整世界观
- 用夜紫、莓黑、樱粉辉光构建“夜樱梦幻版”
- 按钮、边框、卡片高光更像月光照在花瓣上
- 后台也要保持这种夜樱产品感，而不是普通暗黑后台

适用判断：

- 特别重视深色模式能否单独成立
- 希望亮暗两版都有强情绪差异和完整性

## 5. 页面范围

### 5.1 登录页

每套登录页都应体现：

- 品牌标题与副标题
- 主视觉情绪区
- 登录卡片
- 用户名 / 密码输入
- 主按钮 / 次按钮
- 亮色模式展示
- 深色模式展示
- 桌面端与移动端变化

本轮重点观察点：

- 少女风是否自然
- 深色版是否依然梦幻且可读
- 按钮与输入框是否真正有“同一套世界观”

### 5.2 后台配置页

每套后台页都应体现：

- 顶部标题栏
- 操作按钮（刷新、保存）
- 风险提示区
- 配置分组标题
- 多个字段卡片
- 输入框、下拉框、说明文案
- 亮色模式展示
- 深色模式展示
- 桌面端与移动端变化

本轮重点观察点：

- 少女风是否能覆盖到管理台而不违和
- 分组卡片结构是否仍然清晰
- 深色模式下配置页是否依然容易扫读

## 6. 视觉边界

本轮衍生不引入“角色立绘”或完整角色海报区，避免把页面推向强活动页 / 强游戏页。

可以允许的元素：

- 樱花、星点、蝴蝶结、徽章、糖果感微装饰
- 更有情绪的边框、标签、角标
- 更梦幻的背景层和高光

不做的元素：

- 大面积角色立绘
- 重插画叙事构图
- 复杂动态特效
- 脱离业务语义的夸张装饰

这样可以让页面明显偏少女风，但仍保持以后映射回真实产品 UI 的可行性。

## 7. 文件组织

建议新增 6 个文件：

- `ui-previews/style-c1-login.html`
- `ui-previews/style-c1-admin.html`
- `ui-previews/style-c2-login.html`
- `ui-previews/style-c2-admin.html`
- `ui-previews/style-c3-login.html`
- `ui-previews/style-c3-admin.html`

说明：

- 不覆盖现有 `style-c-*.html`
- 新文件视为 Style C 的二轮衍生版本
- 便于用户横向对比原版 C 与 C1 / C2 / C3

## 8. 实现约束

1. 继续使用纯静态 HTML
2. 样式继续写在页面内，保证每个文件独立可打开
3. 不接入业务脚本
4. 不调用真实接口
5. 不修改现有页面入口
6. 不要求真实主题切换逻辑，但页面内要清楚展示亮色与深色效果

## 9. 验收标准

完成后应满足：

1. 新增 6 个 HTML 文件
2. 三套风格都能看出是 Style C 的衍生
3. 三套之间仍有明显差异
4. 每套都覆盖登录页与后台配置页
5. 每个文件都能体现桌面端与移动端
6. 每个文件都能体现亮色与深色模式语言
7. 后台页仍能明确映射 `admin-config-form` 的分组 + 字段卡片结构
8. 用户能够据此继续挑选最接近目标的少女向品牌界面

## 10. 非目标

本轮不包括：

- 直接改造真实 UI
- 编写主题切换功能
- 引入角色立绘系统
- 接入现有前端 JS
- 覆盖登录页和配置页之外的更多真实页面

## 11. 后续衔接

当用户在 C1 / C2 / C3 中确认最终偏好的分支后，下一阶段再进入实现规划，明确：

1. 如何把该风格映射回真实登录页
2. 如何把该风格映射到 `admin-config-form` / `createInput(...)`
3. 公共色板、按钮、输入框、卡片体系如何抽取
4. 亮色 / 深色模式在真实页面中的落地方式
