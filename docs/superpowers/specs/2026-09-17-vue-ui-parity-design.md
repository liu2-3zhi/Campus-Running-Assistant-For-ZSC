# Vue UI 与旧版 UI 视觉一致性修正设计

## 目标

以根目录 `index.html`、`scripts/main.new.js` 和 `styles/style.css` 所呈现的旧版 UI 为唯一视觉基准，修正 `frontend/` 下 Vue 版全部用户端和管理端界面的视觉差异。

验收标准为 A 级：在相同数据、主题、浏览器和视口下，Vue 版与旧版的布局、层级、尺寸、间距、字体、颜色、边框、阴影、文案、控件状态、响应式行为保持一致。允许保留 Vue 的组件拆分、状态管理和请求逻辑，不复制旧版的代码缺陷。

## 范围

- 用户端登录与会话：登录、注册、短信、2FA、游客、会话选择、多账号入口。
- 用户端主界面：桌面和移动端主控制台、地图、运行控制 Tab、任务、历史、日志、签到、参数、通知。
- 用户端弹窗：新手帮助、支付、订单、账单、网络错误、封禁和加载状态。
- 管理后台：全部管理面板、子 Tab、表格、表单、筛选、分页、状态提示和弹窗。
- 全局视觉：浅色、深色、主题背景、按钮、输入框、下拉框、页签、表格、滚动条、动画、空态、加载态和错误态。

## 对照基准

- 视口：桌面 `1440x900`、平板 `1024x768`、移动端 `390x844`。
- 移动端必须使用真实移动 UA、触控和设备上下文，避免仅缩窄窗口导致旧版错误模式。
- 动态账号、任务、订单和统计数据必须固定为同一组测试 fixture，再生成旧版与 Vue 版截图。
- 每个页面至少覆盖默认态、空态、加载态、错误态和主要展开态；后台页面同时覆盖长文本、较宽表格和分页状态。
- 旧版中明显由测试数据或旧代码缺陷造成的异常，不作为必须复刻项，但需在差异清单中记录原因。

## 视觉实现架构

### 全局样式层

新增或整理 Vue 全局样式，使旧版视觉 token 成为稳定来源：

- 将旧版 `styles/style.css` 中的 CSS 变量、页面渐变、面板、按钮、输入框、弹窗、表格、深色模式和滚动条规则迁入 Vue 全局样式。
- 保留 Vue 现有 Tailwind v4 构建方式，视觉以计算后的等效样式验收，不逐一对齐旧版 Tailwind v3 类名。
- 所有全局规则按 `legacy-*` 或无冲突的现有语义类命名，避免覆盖 Tailwind 工具类的隐式行为。
- 主题背景同步仍由现有主题 store 负责，视觉规则不得绕过现有主题接口。

### Vue 组件层

- 保留现有路由、Pinia store、API、Socket.IO 和 composable，不改变后端契约。
- 按旧版 DOM 层级重写组件模板与局部样式，组件继续负责绑定数据、事件和可见性。
- 共享视觉直接使用统一全局类；只在明显减少重复时增加展示组件，不为每个按钮或面板创建包装层。
- 管理后台维持现有 `AdminPanel.vue` 注册结构，逐个子面板替换旧版模板层级和控件状态。
- 移动端继续由 `app.detectMobile()` 驱动，但布局和交互密度必须对应旧版移动容器，而不是桌面组件的压缩版本。

## 数据流

1. 页面进入后仍通过现有路由和认证守卫确定登录、单账号、多账号或主应用状态。
2. 组件通过现有 `api` service 和 Pinia store 获取数据，展示层只消费归一化后的状态。
3. 主题、地图、通知、支付和后台配置继续沿用现有 store 与服务，不在视觉修正中引入第二套状态源。
4. 视觉测试通过 Playwright `route()` 替换 API 响应，保证旧版与 Vue 版使用相同数据。
5. 交互动作仍调用原有 API；视觉验收不修改业务行为，除修复导致显示不一致的明确前端 bug。

## 错误与边界处理

- 网络错误、未认证、封禁、无权限、空数据和接口异常必须保持旧版对应的可见状态与操作入口。
- 长用户名、长任务名、长日志、宽表格和窄屏不能导致文字重叠、按钮换行错位或页面横向溢出。
- 模态框必须恢复旧版的遮罩层级、最大高度、滚动、地图隔离和关闭行为。
- 深色模式下所有新增或迁移样式都必须有明确覆盖，不得只修正浅色截图。
- 加载层和禁用状态必须阻止重复提交，同时保持旧版控件尺寸稳定。

## 实施顺序

1. 建立差异清单和 Playwright 截图基准，覆盖全局样式、登录页和主布局。
2. 先修正全局样式层和公共控件，这些修改会传导到所有页面。
3. 修正登录、会话选择和多账号入口。
4. 修正桌面主界面、移动主界面、地图、控制 Tab 和用户端弹窗。
5. 逐页修正全部管理后台面板及子 Tab。
6. 重新生成三档视口截图，逐页做并排和像素差异复核。
7. 运行前端构建、现有测试以及与 UI 行为直接相关的 Python 测试。

## 验证

- 旧版和 Vue 版对每个页面产出成对截图，按页面记录差异类型、严重级别和修正状态。
- 重点页面同时比较关键元素的 bounding box、字体、颜色、边框、圆角、阴影和层级。
- 使用固定 fixture 复核默认态、空态、错误态、加载态、深色模式和主要弹窗。
- 验证 `npm run build` 成功。
- 运行现有前端行为测试和与登录、支付、后台 UI 相关的 Python 回归测试。
- 最终人工复核所有差异清单项均已关闭，或明确记录为不适用并说明证据。

## 非目标

- 不以旧版代码缺陷作为视觉规范。
- 不借 UI 修正重写认证、支付、地图或后台业务逻辑。
- 不删除旧版入口，也不改变 Vue 路由与 API 的兼容契约。
