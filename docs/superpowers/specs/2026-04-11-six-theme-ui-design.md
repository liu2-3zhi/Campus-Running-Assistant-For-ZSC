# 六套差异化主题 UI 设计

- 日期：2026-04-11
- 主题：以现有 `default` 为基线扩展 6 套差异化完整主题 UI
- 状态：已完成方案确认，待用户审阅书面规格

## 1. 背景

当前仓库在 `ui/` 下已经有 `default-login.html` 与 `default-admin.html` 两个静态预览文件，可作为本轮主题设计的基准参照。用户希望继续基于这一批 UI 预览稿推进，但不再局限于原有的柔和品牌方向，而是扩展为一组差异尽可能大的完整主题系统。

本轮不是简单换色，而是从“主题人格、版式结构、控件材质、信息密度、亮暗模式表达”五个层面同时拉开差距。与此同时，所有方案都必须保持产品可落地性，不能退化为活动页、概念海报或脱离后台配置场景的展示稿。

## 2. 已确认范围

本次设计范围已经确认如下：

1. 输出 **6 套完整主题**。
2. 每套主题都包含：
   - 登录页
   - 后台配置页
3. 每个 HTML 文件都同时展示：
   - 桌面端预览
   - 移动端预览
   - 亮色模式
   - 暗色模式
4. 主题差异要尽可能大，但 **6 套都必须可以落地到真实产品 UI**。
5. 不要求围绕“跑步 / 运动”语义展开，允许使用完全不同的产品人格。
6. 允许出现强人格化主题，例如赛博、东方、杂志、轻奢、二次元等。
7. 允许不同主题使用不同的信息密度，只要仍能完成对应功能表达即可。
8. “以现有 default 为基础”的含义是：
   - 保留登录页与后台配置页的**业务语义**；
   - 不保留当前版式；
   - 可以重做布局、材质、层次与控件表达。
9. 当前 `default` 系列文件需要直接改造成 **二次元风格基线主题**。

## 3. 目标

本次设计的目标是建立一套可横向比较的主题选型系统，让用户能够在同一批预览稿里快速判断：

- 哪种主题人格最适合当前产品；
- 哪种登录页结构更有吸引力；
- 哪种后台配置页既有风格又不影响使用；
- 哪种亮暗模式组合最完整；
- 哪一套最值得进入真实业务页面落地。

换句话说，本轮产出不是最终线上页面，而是用于决策的高完整度静态 UI 主题集。

## 4. 非目标

本阶段不包含以下内容：

1. 不接入真实业务逻辑。
2. 不接入真实接口与真实配置数据。
3. 不改造业务 JS 流程。
4. 不统一整个项目所有页面，只覆盖登录页与后台配置页两类核心页面。
5. 不制作带复杂交互的原型系统。
6. 不通过角色立绘、重插画叙事或强活动页手法制造差异。

## 5. 共通业务语义约束

虽然 6 套主题在视觉与结构上都可以重做，但必须保留以下业务语义，使后续能映射回真实页面。

### 5.1 登录页必须保留的语义

- 品牌标题 / 副标题
- 登录主卡片
- 用户名输入区
- 密码输入区
- 主按钮
- 次按钮或辅助入口
- 辅助说明文案
- 可区分桌面端与移动端层级
- 可区分亮色与暗色模式

### 5.2 后台配置页必须保留的语义

- 页面标题栏
- 主操作按钮（如刷新、保存）
- 风险 / 提示区域
- 配置分组标题
- 多个字段卡片或字段区块
- 输入框、下拉框、说明文案
- 可区分桌面端与移动端布局
- 可区分亮色与暗色模式

### 5.3 可读性与可实现性底线

所有主题都必须满足以下底线：

- 表单字段必须一眼可识别；
- 按钮主次关系必须清楚；
- 后台页必须保留“可配置、可扫读、可操作”的产品语义；
- 提示信息、危险信息、禁用态和聚焦态不能因为风格化而失真；
- 差异来自设计系统，而不是牺牲功能表达。

## 6. 六套主题总览

本轮最终确定的 6 套主题如下：

1. **Anime Core**：二次元产品基线，由 `default` 承载
2. **Neo Minimal**：新极简秩序
3. **Cyber Grid**：赛博网格
4. **Eastern Calm**：东方留白
5. **Editorial Magazine**：杂志编排
6. **Luxe Noir**：轻奢夜宴

说明：

- 原先备选中的 `Nature System` 不进入最终 6 套；
- `default` 不再作为“中性默认样式”，而是升级为明确的 Anime Core 主题；
- 这样最终仍保持 6 套主题总量，同时保证差异足够大。

## 7. 主题详细设计

### 7.1 Anime Core（由 default 承载）

#### 定位

将当前 `default` 改造成“二次元审美下的真实产品 UI 基线主题”。它不是游戏活动页，而是带有梦幻、少女、徽章、缎带、月光、糖霜质感的可用产品界面。

#### 登录页结构

- 桌面端采用“左侧情绪品牌区 + 右侧登录卡”结构；
- 左侧负责建立梦幻入口氛围，可使用星点、樱雾、徽章式标题与柔和品牌文案；
- 右侧登录卡保持标准表单结构，但卡体材质更像“精致角色卡 / 魔法终端卡”；
- 移动端收束为单卡片布局，顶部保留主题徽章、副标题和轻装饰。

#### 后台配置页结构

- 后台定位为“二次元产品控制台”；
- 顶部标题区可使用徽章按钮、状态标签、主题化操作按钮；
- 分组标题采用缎带标签、勋章标签或柔性章节头；
- 字段卡片像“收纳卡 / 指令卡”，大圆角、弱光边界、品牌化说明文案；
- 风险提示区要明显，但语气更像“特殊提示框 / 封印提醒”，而不是纯工业警告条。

#### 亮暗模式策略

- 亮色：樱花粉、奶白、晴空蓝、淡紫；
- 暗色：夜莓紫、月光蓝、深樱粉、柔光高亮；
- 暗色是完整夜间世界观，而不是亮色反相。

#### 控件材质

- 主按钮：柔和渐变 + 轻光泽；
- 输入框：胶囊圆角、珠光边界、很轻的内发光；
- 卡片：雾面半透明或柔雾实底；
- 标签：徽章化、小缎带化；
- 分隔：少用硬线，多用层次与边界光。

#### 边界

允许轻装饰，但不引入大面积角色立绘、夸张特效或重游戏化任务布局。

### 7.2 Neo Minimal

#### 定位

强调秩序、留白、精密和成熟工具感，是 6 套里最克制的一套。

#### 登录页结构

- 桌面端采用大留白背景 + 中央偏右登录卡；
- 左侧只保留极少量品牌语句和简短说明；
- 移动端收束成非常安静的纵向单卡片结构。

#### 后台配置页结构

- 使用窄侧栏 + 宽内容区；
- 配置项以整齐网格、规整间距与稳定对齐组织；
- 信息密度中高，但视觉噪音最低。

#### 亮暗模式策略

- 亮色：纸白、雾灰、冷蓝点缀；
- 暗色：石墨黑、冷白字、极弱高光；
- 亮暗两套都维持高度克制。

#### 控件材质

- 按钮：实底或极轻渐变；
- 输入框：清晰边界、低装饰；
- 卡片：弱阴影、规整圆角；
- 强调排版秩序，不依赖材质表演。

### 7.3 Cyber Grid

#### 定位

最强数字系统感主题，强调网格、发光描边、扫描感和未来终端气质。

#### 登录页结构

- 桌面端采用“左视觉区 + 右认证终端区”布局；
- 左侧体现坐标网格、扫描线、数据面板感；
- 右侧登录区像安全认证终端；
- 移动端表现为掌上控制终端。

#### 后台配置页结构

- 顶部状态条 + 模块化参数面板；
- 分组卡片边界更强，信息密度可提升；
- 整体更像系统控制台而不是传统管理后台。

#### 亮暗模式策略

- 亮色：实验室白、冰蓝、浅青发光；
- 暗色：深蓝紫、青色霓虹、粉紫电光；
- 暗色是主场，亮色是“未来实验室版”。

#### 控件材质

- 按钮：描边发光或渐变发光；
- 输入框：终端框体感更强；
- 卡片：高辨识边界、网格底纹、状态条；
- 状态与聚焦反馈必须非常明确。

### 7.4 Eastern Calm

#### 定位

以东方留白、纸感、印章感和静谧秩序为核心，强调安静但有风骨的产品气质。

#### 登录页结构

- 桌面端采取不对称留白构图；
- 可使用竖向标题、章印式标签、纸感登录卡；
- 移动端收敛成“静室入口”式单卡布局。

#### 后台配置页结构

- 分组像卷轴段落般上下展开；
- 字段卡片更像签条、纸片或册页单元；
- 信息密度中等，强调阅读节奏而非高压信息堆叠。

#### 亮暗模式策略

- 亮色：宣纸白、墨灰、朱砂点；
- 暗色：夜墨黑、暗金灰、深木色；
- 暗色依旧保持沉静，不引入霓虹式高刺激效果。

#### 控件材质

- 输入框与按钮可保留纸感边界；
- 分组标题具备章法与留白；
- 局部使用朱砂 / 暗金作为强调，但不过度装饰。

### 7.5 Editorial Magazine

#### 定位

通过栏目化、强标题、跨栏编排、海报感建立差异，是最依赖版式而不是材质的主题。

#### 登录页结构

- 登录页像一本品牌杂志的封面；
- 允许大标题、强副标题、分栏文本和非对称布局；
- 登录区域不必居中，而是嵌入整个排版系统；
- 移动端转为海报式单列编排。

#### 后台配置页结构

- 配置页更像编辑台 / 内容策展面板；
- 通过栏位、跨栏卡片、标题层级来组织配置项；
- 信息密度可灵活，但必须保证栏目关系一眼可懂。

#### 亮暗模式策略

- 亮色：黑白灰主体 + 单一强调色；
- 暗色：高反差排版 + 大面积深底；
- 视觉重点是编排关系和标题系统，而不是装饰光效。

#### 控件材质

- 控件材质简洁，避免抢走版式风头；
- 重点在标题尺度、留白节奏、栏目切分与辅助字阶梯。

### 7.6 Luxe Noir

#### 定位

以黑金、丝绒、金属边框、暖色光泽和高端品牌控制台感建立最强戏剧化气质。

#### 登录页结构

- 桌面端采用中轴或准中轴构图；
- 品牌区营造高端门厅 / 夜宴入口的仪式感；
- 登录卡像高定卡盒或品牌会所控制入口；
- 移动端保留“高定卡片”与边框光泽感。

#### 后台配置页结构

- 后台更像高层品牌运营总控台；
- 标题区、操作区、统计区和分组区层级明显；
- 配置分组可采用框景式布局，增强戏剧性与尊贵感。

#### 亮暗模式策略

- 亮色：象牙白、香槟金、暖灰；
- 暗色：黑金、酒红、铜色高光；
- 暗色是主叙事版本，亮色是高端日间版。

#### 控件材质

- 按钮：金属边界、深色高光、暖色点亮；
- 输入框：丝绒底感或雾面深底；
- 卡片：框线感强，层级与戏剧化对比更明显。

## 8. 共通结构与状态设计约束

### 8.1 响应式展示策略

每个 HTML 文件内都同时展示桌面端与移动端，不依赖用户手动缩放浏览器。

建议采用双区或多卡并列方式，让用户在同一页内完成横向比较。

### 8.2 亮暗模式展示策略

每个 HTML 文件都同时呈现亮色与暗色的完整效果，而不是只做其中一个模式。这样可以直接验证：

- 主题在两种模式下是否仍然属于同一世界观；
- 暗色是否是独立成立的完整版本；
- 配置页在暗色下的扫读性是否足够。

### 8.3 状态设计要求

所有主题都必须能表达以下状态：

- 默认态
- Hover / Focus 态
- 主按钮态 / 次按钮态
- 风险提示态
- 禁用态
- 表单输入聚焦态

其中：

- 风险提示区必须在后台页明显可见；
- 登录失败或字段错误的视觉语义必须与正常提示区明显区分；
- 聚焦态不能只靠颜色变化到几乎不可见。

### 8.4 信息密度策略

允许不同主题采用不同密度：

- Neo Minimal、Cyber Grid：偏中高密度；
- Eastern Calm：偏中密度；
- Editorial Magazine、Luxe Noir：以编排层级拉开感受，不强制高密度；
- Anime Core：中等密度，优先兼顾主题感与可读性。

## 10. 验收标准

完成后的设计预览稿应满足：

1. 明确产出 6 套主题。
2. 每套都包含登录页与后台配置页。
3. 每个 HTML 文件都能同时看到桌面端与移动端。
4. 每个 HTML 文件都能同时看到亮色与暗色。
5. 六套主题在世界观、版式、控件材质和信息密度上都能明显区分。
6. 后台配置页在所有主题下都仍然可读、可扫读、可映射回真实配置场景。
7. `default` 成功转为二次元风格，并且不是简单套粉色，而是完整成立的 Anime Core 产品主题。

## 11. 验证方式

本轮验证以静态预览为主，重点检查以下问题：

1. 用户是否能一眼看出 6 套主题差异；
2. 用户是否能快速判断自己偏好的主题人格；
3. 登录页是否既有主题氛围又不失去表单识别；
4. 后台页是否在保留配置语义的同时完成风格迁移；
5. 暗色模式是否不是附属版，而是完整版本；
6. Anime Core 是否达到“二次元产品 UI”而非“活动海报”的边界。

## 12. 后续衔接

本设计文档确认后，下一步进入实现规划阶段，明确：

1. 每个 HTML 文件的具体结构拆分；
2. 6 套主题的开发顺序；
3. 哪些样式能复用，哪些必须分开实现；
4. `default` 改造为 Anime Core 时需要保留或替换的核心区块；
5. 如何在不接入业务逻辑的前提下，让每套预览稿都足够完整可比较。
