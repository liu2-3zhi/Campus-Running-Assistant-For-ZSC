# MySQL 文档存储 v1 历史设计

本文仅记录旧版 v1 背景，**不再作为当前部署或迁移指南**。当前权威说明见[数据库优先存储设计](database-first-design.md)、[实施计划](database-first-plan.md)和[数据库存储与离线迁移](mysql-storage.md)。

## v1 原有边界

旧 v1 以文档表保存 JSON/INI 原始字节、命名空间、修改时间、摘要和修订号，另有就绪状态表；业务通过 `storage_io` 局部代理访问文档。当时仍有可选文件运行后端，本地主配置作为引导，日志和图片等资源保持磁盘路径。

以上均为历史行为。实体与关系藏在整份文档内，不利于约束和按字段查询；简单复制为多张同构 BLOB 表也不能解决，因此 v2 改为按身份、会话、支付、任务、内容、背景和配置领域拆表。

## v2 替代方式

当前只允许 SQLite/MySQL 运行，默认 SQLite 用于本地开发测试，`file` 冻结并拒绝。领域核心类型列是权威值，兼容 registry 只保存结构和来源元数据；主配置及信任 IP 也入库。日志位置、归档、挂载与磁盘资源不变，单应用实例约束仍有效。

旧 v1 文档库仅通过显式离线 `--source legacy-mysql` 只读迁移。同库升级必须使用不同目标前缀；v1 未包含的本地主配置与信任 IP 要单独核对，不能据此声称整个部署完整迁移。当前导出用于备份和再次导入数据库，不重新启用文件运行后端；命令与备份限制以[当前迁移指南](mysql-storage.md)为准。
