# 可选 MySQL 存储设计

## 目标与范围

默认继续使用现有文件后端；显式启用 MySQL 后，以文档表保存原 JSON/INI 的字节和命名空间，不改账号、权限、UA、订单及账单数据形状。覆盖系统账号、学校账号、会话、Token、后台任务、订单、账单、删除账号备份、自动签到配置、消息、提醒及背景身份状态。主配置 configs/config.json 和数据库连接环境变量保留在本地，避免循环引导。

日志目录（含自定义 Logging.log_dir）整棵排除；logs 下的 JSON 状态、归档、验证码、支付和账单日志也保持原位。上传文件、图片、SSL、缓存及程序文件继续存磁盘。

## 实现边界

- business_storage.py：严格配置、路径白名单、MySQL 参数化 CRUD、文档版本及事务。连接按操作创建，事务内部复用同线程连接，退出关闭；禁止共享跨线程连接。
- storage_io.py：显式导入到业务模块的局部兼容接口，覆盖 open、目录枚举/存在性/删除/移动、INI 读取、临时文件原子替换。不修改 builtins 或标准库全局对象。受管文档只读数据库，旧物理文档不回退，未受管路径走原文件系统。
- storage_migration.py / tools/migrate_storage.py：离线扫描、建表、导入、摘要校验与导出。源文件不删除；同内容幂等，冲突默认失败，源数据预检查后分批事务写入；校验通过后标记数据库可供运行。
- APP_STORAGE_BACKEND=file/mysql；凭据仅环境变量。MySQL 不可用明确失败，不写回文件。默认不迁移当前用户数据。

## 一致性与限制

单文档写入原子提交；r+ 使用版本检查，发现并发覆盖则失败。既有业务锁继续约束一个应用实例，首版不宣称多实例事务正确性或自动分库。迁移前停止应用，迁移后核对数量和 SHA256；切回文件前停服并导出最新数据库内容，不能直接使用陈旧源文件。

运行期根目录和工作目录必须与代码根目录一致；离线迁移工具可单独指定源根目录。数据库摘要使用持久化字段核验，就绪标志必须在迁移开始时关闭、完整核验后开启。Compose 覆盖文件只连接外部 MySQL，不内置数据库服务或改变日志挂载。

3. 接入所有持久化业务模块与启动检查，补真实业务入口测试；保留缓存与日志模块的磁盘行为。
4. 提供可选 MySQL Compose 覆盖配置和使用文档，验证迁移/导出往返及数据库故障不回退。
5. 独立审查、完整 Python/JavaScript 回归及可用环境下的真实 MySQL 集成验证，明确未验证边界后提交。
