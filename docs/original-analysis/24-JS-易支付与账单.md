# 模块 1：密码恢复任务管理（58399–58931）

## 1.0 `beforeunload` 事件监听器（58401–58406）
- **绑定**：`window.addEventListener("beforeunload", ...)`
- **职责**：页面卸载前清理 `multiAccountAutoRefreshInterval`（多账号自动刷新定时器），置 `null`，防止内存泄漏。
- **副作用**：`clearInterval`。

## 1.1 `updateBruteforceTaskList(tasks)`（58443–58635）
- **职责**：将后端返回的"密码恢复（暴力破解）任务"状态数组渲染到桌面版与移动版两个容器。
- **参数**：`tasks` (Array) — 每项含 `account`、`status`(`running`/`success`/`failed`/`stopped`)、`attempts`、可选 `password`、`start_time`、`end_time`。
- **返回值**：无（void）。
- **DOM 元素**：
  - `#bruteforce-task-list`（桌面版容器）
  - `#mobile-bruteforce-task-list`（移动版容器）
- **业务逻辑**：
  - 空/空数组时插入"暂无任务"占位（桌面 `py-8 text-sm`，移动 `py-4 text-xs`）后返回。
  - 状态→颜色/图标/文本映射：`success`=green/✅/成功；`failed`=red/❌/失败；`stopped`=orange/⏸️/已停止；默认 slate/⏳/运行中。
  - 卡片使用模板字符串拼接（Tailwind `border-${statusColor}-200 bg-${statusColor}-50` 等动态类）。
  - 仅当 `status === "running"` 渲染"停止"按钮，`onclick="stopBruteforce('${task.account}')"`（`stopBruteforce` 为外部函数）。
  - 成功时以绿色加粗显示 `密码: ${task.password}`；桌面版额外显示 `开始时间`，移动版省略。
- **副作用**：直接 `innerHTML` 覆盖两个容器。
- **绑定事件**：卡片内联 `onclick=stopBruteforce(account)`。

## 1.2 限流全局变量（58694–58696）
- `lastInitialDataRequest = 0`（上次请求时间戳）
- `lastInitialDataResponse = null`（缓存响应）
- `INITIAL_DATA_RATE_LIMIT = 500`（限流窗口 500ms）

## 1.3 `getInitialDataFailureNotice(response)`（58698–58720）
- **职责**：根据初始数据响应生成失败提示对象（供 `loadInitialData` 弹窗使用）。
- **参数**：`response`。**返回值**：`null`（无需提示）或 `{ title, text, icon }`。
- **逻辑**：`success !== false` 或 `stale_auth_response`/`suppressed` 时返回 `null`；`offline` 且无 message 也可返回 offline 文案；`offline` → 标题"后端连接异常" icon `warning`，否则"初始化失败" icon `error`。

## 1.4 `loadInitialData(options = {})`（58741–58931，async）
- **职责**：统一封装 `get_initial_data` 调用，带限流、缓存、失败提示、超管任务列表自动更新、多账号状态、权限组同步。
- **参数**：`options.frontend_logs`（要上报的前端日志）、`options.force`（忽略限流）。
- **返回值**：`Promise<Object>`（完整响应，即使 `success:false` 也返回）；异常时 `throw`。
- **后端 API**：`callPythonAPI("get_initial_data", params)`（非 fetch）。
- **业务逻辑/副作用**：
  1. 限流：非 force 且距上次 <500ms 且有缓存 → 直接返回缓存（并调用 `syncMapProviderConfigFromInitialData`）。
  2. 有 `frontend_logs` 时并入 params。
  3. 更新 `lastInitialDataRequest`，await 调用后缓存到 `lastInitialDataResponse` 并同步地图配置。
  4. 失败提示：`getInitialDataFailureNotice` 非空则 `Swal.fire`。
  5. `success` 时：存在 `bruteforce_task_list` → 调 `updateBruteforceTaskList`（仅超管有此字段）；存在 `accounts` 数组 → 记日志；存在 `auth_group` → 同步 `currentUserData.auth_group/group`。
  6. `logMessage_Info` 记录完成。

# 模块 2：彩虹易支付系统 - 用户端前端（58933–60178）

## 2.0 全局变量（58948–58964）
| 变量 | 初值 | 说明 |
|---|---|---|
| `paymentPollingTimer` | `null` | 订单轮询定时器（`setInterval` 句柄） |
| `paymentPollingCount` | `0` | 已轮询次数 |
| `currentOrdersPage` | `1` | 订单列表当前页 |
| `ordersPerPage` | `10` | 每页订单数 |
| `currentOrderStatus` | `"all"` | 当前筛选状态（all/pending/paid/closed） |

## 2.1 `openPaymentModal()`（58983–59123，async）
- **职责**：打开支付弹窗、重置表单、动态加载"启用的支付方式"单选列表。
- **返回值**：无。
- **后端 API**：`GET /api/admin/payment/config`（头带 `X-Session-ID`）。
- **DOM 元素**：`#payment-modal`（移除 `hidden`、`display=flex`）、`#payment-amount`（清空）、`#payment-product-name`（重置为"在线支付"）、`#payment-methods-container`（动态填充）。
- **业务逻辑**：
  - 读取 `result.enabled_payment_methods`；为空 → 显示"暂无可用的支付方式"占位并 return。
  - 遍历方式，从 `PAYMENT_METHODS[method]` 取配置（缺省用 fallback），首项 `checked`；用 `insertAdjacentHTML("beforeend", ...)` 追加 `<label><input type="radio" name="payment-method" value="${method}">`。
  - 失败/异常 → `Swal.fire` 提示。

## 2.2 `closePaymentModal()`（59142–59155）
- **职责**：隐藏支付弹窗。**DOM**：`#payment-modal`（加 `hidden`、`display=none`）。无 API。

## 2.3 `createPaymentOrder()`（59177–59330，async）
- **职责**：校验输入→验证域名→创建订单→新窗口打开支付页→启动轮询。
- **返回值**：`Promise<void>`。
- **DOM 输入**：`#payment-amount`、`input[name="payment-method"]:checked`、`#payment-product-name`。
- **校验规则**：金额非空、`>= 0.01`；必选支付方式；商品描述非空（均用 `showModalAlert`）。
- **后端 API**：
  1. `POST /api/payment/verify_host`，body `{ app_host }`（`app_host = protocol//host`）。失败 → 提示 return。
  2. `POST /api/payment/create`，body `{ amount, payment_type:"jump", payment_method:payType, product_name, app_host, return_url:location.href, sub_openid, sub_appid, device:Get_YiPAi_device() }`。
- **成功副作用**：取 `pay_url`/`order_id` → `closePaymentModal()` → `window.open(payUrl, "_blank")` → `showModalAlert("请在新打开的页面完成支付…")` → `startOrderPolling(orderId)`。
- **异常**：`showModalAlert("网络错误…")`。

## 2.4 `queryOrderStatus(orderId)`（59350–59383，async）
- **职责**：查询单个订单状态。**参数**：`orderId`。**返回值**：`Promise<Object>`（后端结果，或 `{success:false,message}`）。
- **后端 API**：`POST /api/payment/query`，body `{ order_id }`。
- **备注**：订单状态语义 `pending`/`paid`/`closed`。

## 2.5 `startOrderPolling(orderId)`（59407–59493）
- **职责**：启动订单状态轮询状态机。
- **副作用/轮询参数**：
  - 先 `clearInterval(paymentPollingTimer)`，重置 `paymentPollingCount=0`。
  - `setInterval` **每 3000ms** 执行；最多 **20 次**（≈1 分钟）。
  - 每次 `queryOrderStatus`：`status==="paid"` → 清定时器 + `Swal` 成功 + 若 `#orders-modal` 打开则 `loadPaymentOrders(currentOrderStatus, currentOrdersPage)`；`status==="closed"` → 清定时器 + `Swal` info。
  - `paymentPollingCount>=20` → 清定时器 + `Swal` warning（查询超时）。
- **DOM**：读取 `#orders-modal` 的 `display` 判断是否刷新列表。

## 2.6 `openOrdersModal()`（59512–59544）
- **职责**：打开"我的订单"弹窗并加载第 1 页全部订单。
- **DOM**：`#orders-modal`（显示）；`.orders-filter-btn`（重置激活态，仅 `data-status="all"` 加 `active bg-sky-500 text-white`）。
- **副作用**：`currentOrderStatus="all"`、`currentOrdersPage=1`、`loadPaymentOrders("all", 1)`。

## 2.7 `closeOrdersModal()`（59558–59577）
- **职责**：隐藏订单弹窗并停止轮询。
- **DOM**：`#orders-modal`（隐藏）。**副作用**：`clearInterval(paymentPollingTimer)`。

## 2.8 `loadPaymentOrders(status, page)`（59597–59694，async）
- **职责**：拉取并渲染订单列表 + 更新分页。
- **参数**：`status`、`page`。**返回值**：`Promise<void>`。
- **DOM**：`#orders-list-container`（先显示"加载中…"，后填充卡片或空态 SVG）。
- **后端 API**：`GET /api/payment/orders?page=${page}&per_page=${ordersPerPage}`，`status!=="all"` 时追加 `&status=${status}`。
- **逻辑**：`total`、`totalPages=Math.ceil(total/ordersPerPage)`；遍历 `orders` 调 `createOrderCard` 并 `insertAdjacentHTML`；结束调 `updateOrdersPagination(page, totalPages)`。
- **异常**：容器显示"网络错误"。

## 2.9 `createOrderCard(order)`（59710–59862）
- **职责**：返回单个订单卡片 HTML 字符串。**返回值**：`string`。
- **逻辑**：
  - 状态样式 `statusConfig`：`pending`=amber/待支付；`paid`=green/已支付；`closed`=slate/已关闭；默认未知。
  - 支付方式文本：`alipay`=支付宝、`wxpay`=微信支付、`bank`=网银支付、其他原样。
  - 时间：`new Date(order.create_time).toLocaleString("zh-CN", {...hour12:false})`。
  - 金额：`¥${parseFloat(order.amount).toFixed(2)}`。
  - 按钮：`pending` → "继续支付"(`continuePay(order_id)`) + "查询状态"(`refreshOrderStatus(order_id)`)；其它 → 仅"查询状态"。

## 2.10 `updateOrdersPagination(currentPage, totalPages)`（59878–59912）
- **职责**：更新订单分页控件。
- **DOM**：`#orders-page-info`（`第 X / Y 页`）、`#orders-prev-btn`、`#orders-next-btn`（首/末页时 `disabled` + `opacity-50 cursor-not-allowed`）。

## 2.11 `continuePay(orderId)`（59928–59981，async）
- **职责**：继续支付未完成订单。
- **后端 API**：`queryOrderStatus(orderId)`（→ `POST /api/payment/query`）。
- **逻辑**：查询失败/非 `pending` → 提示 return；否则取 `result.order.pay_url` → `window.open(_,"_blank")` → `startOrderPolling(orderId)` → `Swal` info（2s 定时）。

## 2.12 `refreshOrderStatus(orderId)`（59997–60067，async）
- **职责**：手动刷新单订单状态并重载列表。
- **后端 API**：`queryOrderStatus` → `POST /api/payment/query`。
- **逻辑**：显示 `Swal` loading → 查询 → `Swal.close()` → 结果映射（paid=success/pending=info/closed=warning/默认 question）弹窗 → `loadPaymentOrders(currentOrderStatus, currentOrdersPage)`。

## 2.13 用户端支付 DOMContentLoaded 事件绑定（60073–60178）
在 `DOMContentLoaded` 内绑定：
| DOM id / selector | 事件 | 处理 |
|---|---|---|
| `#payment-close-btn` | click | `closePaymentModal` |
| `#payment-cancel-btn` | click | `closePaymentModal` |
| `#payment-submit-btn` | click | `createPaymentOrder` |
| `#payment-modal` | click | 点击背景(`e.target===modal`)关闭 |
| `#orders-close-btn` | click | `closeOrdersModal` |
| `#orders-refresh-btn` | click | `loadPaymentOrders(currentOrderStatus, currentOrdersPage)` |
| `#orders-modal` | click | 点击背景关闭 |
| `.orders-filter-btn`（多个） | click | 切换 active，`loadPaymentOrders(this.dataset.status, 1)` |
| `#orders-prev-btn` | click | 若 `currentOrdersPage>1` 加载上一页 |
| `#orders-next-btn` | click | 加载下一页 |

# 模块 3：彩虹易支付系统 - 管理员功能（60180–60988）

## 3.0 全局变量（60192–60195）
- `currentPaymentLogsPage = 1`
- `paymentLogsPerPage = 20`

## 3.1 `loadPaymentConfig()`（60214–60373，async）
- **职责**：加载支付配置并渲染成"启用支付方式"复选框列表（管理员）。
- **后端 API**：`GET /api/admin/payment/config`。
- **DOM**：`#mobile-multi-admin-payment-config-content`（动态填充）；生成 `#payment-method-${methodCode}` 复选框、`#save-payment-config-btn`（保存按钮，绑定 `savePaymentConfig`）、`#payment-config-loading`（隐藏加载态）。
- **逻辑**：`enabled_payment_methods` 决定复选框 `checked`；遍历 `Object.entries(PAYMENT_METHODS)` 生成条目（SVG 或 emoji 图标）。

## 3.2 `savePaymentConfig()`（60392–60485，async）
- **职责**：收集勾选的支付方式并保存。
- **逻辑**：遍历 `Object.keys(PAYMENT_METHODS)` 读 `#payment-method-${code}.checked`；空 → warning return；`join(",")` 成字符串。
- **后端 API**：`PUT /api/admin/payment/config`，body `{ enabled_payment_methods: "alipay,wxpay" }`。
- **结果**：成功 `Swal` success（2s）；失败/异常 `Swal` error。

## 3.3 `loadPaymentLogs(page)`（60504–60690，async）
- **职责**：按筛选条件加载支付日志并渲染。
- **参数**：`page`。**副作用**：更新 `currentPaymentLogsPage`。
- **DOM 输入（筛选）**：`#payment-logs-user-id`、`#payment-logs-action-type`、`#payment-logs-start-date`、`#payment-logs-end-date`。
- **DOM 输出**：`#mobile-multi-admin-payment-logs-list`（加载中/空态 SVG/卡片）。
- **后端 API**：`GET /api/admin/payment_logs?page=&per_page=${paymentLogsPerPage}`，可选追加 `&user_id=&action_type=&start_date=&end_date=`（均 `encodeURIComponent`）。
- **HTTP 错误处理**：`!response.ok` 时读取错误体，401="未登录或会话已过期"、403="权限不足，需要审计日志查看权限"，容器显示红字并 return。
- **逻辑**：`totalPages=Math.ceil(total/paymentLogsPerPage)`；遍历 `logs` 调 `createPaymentLogCard`；结束 `updatePaymentLogsPagination(page, totalPages)`。

## 3.4 `createPaymentLogCard(log)`（60706–60856）
- **职责**：返回单条支付日志卡片 HTML。**返回值**：`string`。
- **操作类型样式** `actionConfig`（`log.action`）：`create_order`=blue/创建订单；`query_order`=purple/查询订单；`payment_success`=emerald/支付成功；`payment_fail`=red/支付失败；`config_update`=amber/配置更新；默认 slate。
- **逻辑**：时间 `toLocaleString("zh-CN")`；`log_data` 若为 JSON 串则 `JSON.stringify(_,null,2)` 用 `<pre>` 展示，解析失败原样展示；金额 `¥${parseFloat(amount).toFixed(2)}` 或 `-`；`log_id` 存在时渲染"查看详情"按钮 `onclick="showPaymentLogDetail('${safeLogId}')"`（`safeLogId` 单引号转义，`showPaymentLogDetail` 为外部函数）。
- **明细行**：订单号/用户ID/状态/金额/记录时间/日志ID。

## 3.5 `updatePaymentLogsPagination(currentPage, totalPages)`（60872–60906）
- **DOM**：`#payment-logs-page-info`、`#payment-logs-prev-btn`、`#payment-logs-next-btn`（同订单分页禁用逻辑）。

## 3.6 管理员支付 DOMContentLoaded 事件绑定（60912–60984）

# 模块 4：欠费检查功能（60990–62152）

## 4.1 `checkOverdueBeforeStart(schoolUsernameOrList = null)`（61024–61089，async）
- **职责**：任务启动前检查欠费；有欠费则弹窗并阻止（返回 `false`），否则/容错返回 `true`。
- **参数**：`null`=检查当前用户全部账号；`string`=单账号；`string[]`=多账号。
- **后端 API**：`POST /api/check_overdue`，body 分支：`{ school_username }` / `{ school_usernames: [...] }` / `{}`。
- **逻辑**：`!result.success` → `showModalAlert` 并返回 `true`（容错不阻塞）；`result.has_overdue` → `await showOverduePaymentModal(result.overdue_accounts)` 后返回 `false`；异常 catch 返回 `true`。

## 4.2 `_requirePaymentForOverdueCache`（61091）+ `_isPaymentRequiredForOverdueCheck()`（61096–61140，async）
- **职责**：判断后端是否开启"欠费需付费"，带 30s 缓存。
- **缓存对象**：`{ value, ts }`，命中窗口 `30 * 1000` ms。
- **后端 API**：`GET /api/config/pricing`。读取 `result.config.require_payment`（布尔或字符串 "true"）。
- **回退**：请求失败 → 读 `#pricing-require-payment_modal` 复选框 `checked`（不存在默认 `true`）。

## 4.3 `_isInMultiAccountModeForOverdueCheck()`（61142–61150）
- **职责**：判断当前是否多账号模式。**DOM**：`#multi-account-app`、`#mobile-multi-account-app`（非 hidden）或 `window.mobileAdminPanelMode==="multi"`。

## 4.4 `_getMultiAccountListUsernames()`（61152–61163）
- **职责**：从多账号列表收集去重用户名。**DOM**：`#multi-account-list`、`#mobile-multi-account-list` 内 `[data-username]`。**返回**：`Array<string>`。

## 4.5 `_checkOverdueBeforeStartByCurrentMode()`（61165–61186，async）

## 7.21 `showRemovedAccountDetail(authUsername)`（65661–65889，async）
- **职责**：展示已删除账号完整详情（基础信息/学校账号/权限组/留言/账单）。

- **DOM/展示**（Swal 宽度移动 `95vw`/PC `680px`）：
  - 头像+用户名+昵称；手机/登录IP/最后登录/注册/注销时间。
  - 有权限学校账号（`_buildRemovedSchoolAccountsHtml`，每项含"查看账号详情"→`View_details_...`）。
  - 权限组：组标识/名称 + 组内权限/自定义追加/自定义移除/最终生效权限（均经 `translatePermission` 翻译成徽章）。
  - 留言记录（最多 30 条，现存/已删标记 + 时间 `_formatUnixOrIsoTime`）。

## 7.22 `restoreAccount(auth_username)`（65894–66126，async）
- **职责**：恢复已删除账号，内置**用户名冲突/手机号冲突**循环解决。
- **后端 API**：`POST /api/admin/restore_account`，body `{ auth_username, restore_as, [phone_override], [force_phone_clear] }`。
- **返回值**：`Promise<boolean>`（成功 `true`）。
- **状态机**：
  - 二次确认弹窗；否则 return false。
  - `for (attempt<10)` 循环：
    - `data.success` → success 弹窗(3s) + `loadRemovedAccountsList()` + return true。
    - `data.conflict==="username"` → 弹窗输入新用户名(`#swal-new-username`)，更新 `restoreAs` 后 `continue`。
    - `data.conflict==="phone"` → 弹窗输入新手机号(`#swal-new-phone`)，留空/同冲突号 → `phoneOverride=""` + `force_phone_clear=true`，否则设新号；`continue`。
    - 其它错误 → error 弹窗 return false。
  - 超 10 次 → "操作失败"弹窗 return false。

## 7.23 `restoreAccountAndRefreshMobile(auth_username)`（66128–66131，async）
- **职责**：移动端恢复账号成功后刷新移动列表（`restoreAccount` → 成功则 `loadMobileMultiRemovedAccountsList()`）。
