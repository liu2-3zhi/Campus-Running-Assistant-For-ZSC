## 2. 移动端通知与签到 UI

### switchMobileNotifTab(tabName) — 43157
- 职责：切换"全部通知 / 签到任务"两个 tab 的高亮样式与显隐。
- DOM：`#mobile-notif-tab-all`、`#mobile-notif-tab-attendance`、`#mobile-all-notifications-list`、`#mobile-attendance-notifications-list`。
- 逻辑：`tabName==="all"` 时显示全部列表，否则显示签到列表；通过替换 `className` 和 `hidden` 类切换。

### mobileRefreshNotifications(showalert=true) — 43180 `async`
- 职责：刷新通知。调用 `fetchNotifications()`（外部）后 `updateMobileNotificationUI()`。
- DOM：`#mobile-refresh-notifications-btn`（禁用/恢复）。
- 副作用：`showalert` 时弹三段提示（刷新中/完成/失败）。
- 注意 bug：`originalText` 在 `if(btn)` 块内声明（`const`），`finally` 中引用 `typeof originalText` 恒为 `undefined`（作用域问题），按钮文本会被重置为"刷新"。

### updateMobileNotificationUI() — 43209
- 职责：根据 `window.currentNotifications` 渲染未读徽标 + 两个通知列表。
- DOM：`#mobile-notification-badge`（未读数 `>9` 显示 `9+`）、`#mobile-all-notifications-list`、`#mobile-attendance-notifications-list`。
- 逻辑：签到通知按 `n.image==="attendance"` 或标题含"签到"过滤；每条含 `attendance_code`（-1 已过期 / 1 已签到 / 0 待签到→显示"签到"按钮 `onclick="mobileHandleAttendance(id)"`）。
- 事件：普通通知项 `click` → `markMobileNotificationRead(notice.id)`。

### syncMobileAttendanceList() — 43317
- 职责：渲染 `#mobile-attendance-list` 签到卡片（更细粒度，含随机签到/补签/地图选点签到按钮）。
- 逻辑：从 `n.updateBy`（`"lat,lon"` 字符串）解析目标坐标 `targetCoords=[lon,lat]`。按 `attendance_code` 渲染：
  - `0` 待签到 → 三按钮：`handleAttendance(event, id, coords)`、`handleMakeupAttendance(...)`、`openMobileMapAttendanceModal(id, coords)`。
  - `-1` 已过期 → 仅"随机补签"。
  - `1` 已签到 → 无按钮。
  - `attendance_status_text` 含"失败"时覆盖状态文本为红色。

### markMobileNotificationRead(noticeId) — 43415 `async`
- API：`callPythonAPI("mark_notification_read", noticeId)`；成功后 `mobileRefreshNotifications()`。

### mobileMarkAllAsRead() — 43425 `async`
- 职责：一键已读。过滤 `!isRead` 通知，`Promise.all` 逐条 `mark_notification_read`，完成后刷新。无未读时提示"没有未读通知"。

### expandMobileNotifications() — 43446
- 调用外部 `showNotifications()`。

### mobileHandleAttendance(rollCallId) — 43449 `async`
- 职责：从 `currentNotifications` 找到通知，解析 `updateBy` 坐标，调用 `callPythonAPI("trigger_attendance", rollCallId, targetCoords, "random", null, false)`。成功后刷新通知。

## 9. 移动端面板切换体系

移动端有**单账号**与**多账号**两套面板，切换逻辑分离但函数结构对称。

### openMobileAdminPanelUnified(mode) — 44969
- 职责：打开统一管理面板。`mode` ∈ `'single'`/`'multi'`。
- 逻辑：置 `window.mobileAdminPanelMode`；更新 `#mobile-admin-panel-unified-status` 文本；`single` 调 `switchMobileSinglePanel("mobile-admin-panel-unified")`，`multi` 调 `switchMobilePanel(..., "multi")`；延时 50ms 调 `initMobileAdminPanel("mobile-admin-panel-unified")`。

### switchMobileSinglePanel(panelId, showalert=true) — 44999
- 职责：**单账号模式**面板切换。`singleModePanels` 列表（control/map/task/task-details/notification/log/checkpoints/attendance/admin/admin-panel-unified/settings/profile/task-history）逐一隐藏，显示目标。
- 各面板激活钩子（延时初始化）：control→首次初始化地图；settings→`updateParamInputs`+`refreshMobileSettings`；map→`drawOnMap`+`ensureRunnerMarker`；attendance→加载签到配置 + `refreshNotificationsUI`；task-details→`loadMobileTaskDetails`；profile→`loadMobileUserDetails`；admin→`initMobileAdminPanel("mobile-admin-panel")`；notification→`mobileRefreshNotifications`；task-history→`loadMobileTaskHistoryPanel`；task→`mobileRefreshTasks`；checkpoints→`renderMobileCheckpointsList`。
- 末尾：`updateMobileNavActiveState` + `updateMobileSidebarActive`，`scrollTo top`。

### switchMobileMulitPanel(panelId, mode="multi") — 45263（别名 `switchMobilePanel` — 45426）
- 职责：**多账号模式**面板切换。`multiModePanels`（multi-account/multi-map/multi-control/admin-panel-unified/multi-settings/multi-log）。
- 激活钩子：multi-control→首次初始化多账号地图；settings/multi-settings→`updateParamInputs`（含自动签到 `mobile-multi-auto_attendance_*` 初始化）；admin-panel-unified→置 `mobileAdminPanelMode="multi"`。

### scrollToMobileSection(sectionId) — 45429
- `scrollIntoView` 平滑滚动 + 更新导航激活态。

### updateMobileNavActiveState(activeSectionId) — 45441
- 更新 `.mobile-nav-btn`（`data-nav`）激活态，`sectionNavMap` 映射面板→导航类型。

### updateMobileSidebarActive(panelId) — 45467
- 更新侧边栏 `.mobile-sidebar-item` 高亮。`panelToMenuText` 映射面板→菜单文本；据 `panelId.includes("multi")` 或 `mobileAdminPanelMode==="multi"` 选择 `#mobile-sidebar-multi-account`/`#mobile-sidebar-single-account`。

### openMobileAccountParams(username) — 45545 `async`
- 职责：打开单账号参数设置模态框 `#mobile-account-params-modal`。
- API：`callPythonAPI("multi_get_account_params", username)` 加载；保存时逐字段 `callPythonAPI("multi_update_account_param", username, key, value)`。
- DOM：`#mobile-account-params-title/container`，`#mobile-save-account-params-btn`；用 `createParamInputs`/`updateParamInputs`（排除"主题与外观"组）。

## 附：已发现的潜在缺陷（复刻时留意）

1. `mobileRefreshNotifications`（43180）`originalText` 作用域错误，`finally` 中恒为 `undefined`，按钮文本被重置为"刷新"。
2. `showMobileResetPassword`（55046）清空 `#mobile-new-password`，但真实输入框 id 为 `#mobile-new-password_2`（55088 又引用了不存在的旧 id）。
3. `escapeHtml`（45668/49518）、`toggleMobileTaskDetails`（44234/56279）、`toggleMobileNotifications` 等**重复定义**，后者覆盖前者。
4. `submitMobileModifyPhone`（53197）用 `/auth/modify_phone`，而统一面板 `confirmMobileUnifiedModifyPhone`（53747）用 `/api/user/update_phone`——两套改手机号 API 并存。
5. `editormd` 各编辑器 `htmlDecode` 键在同一对象内被写两次（`true` 后又 `"style,iframe,image"`），后者生效。
