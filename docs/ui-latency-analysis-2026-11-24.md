# 2026-11-24 WebUI 延迟与重复 CDN 下载分析

## 结论

本次日志中的重复缓存来自启动后无条件执行的 CDN 全量更新。WebUI 延迟还存在两个独立的放大因素：前端日志上传反复触发完整业务初始化；用户列表的文件兼容接口在关系数据库中逐条重建文档，并在更新登录缓存时持锁执行整表版本检查。读取前端配置时额外回写数据库，也增加了请求开销。

本轮修复位于源码仓库，尚未构建或部署新镜像。没有修改远端业务数据库、表结构和日志目录。以下请求时长来自修复前日志，不能作为修复后的线上性能数据。

## 分析依据

- 服务端日志：`C:\Users\Zelly\Desktop\数据\python_running-new\logs\zx-slm-tool.log`，本次快照约 4,370 行。
- 同目录的 WARNING 和 ERROR 日志。
- 用户提供的浏览器控制台附件。
- `web_server.py`、`scripts/main.js`、`auth_system.py`、`storage_io.py` 与 `persistence/store.py` 的调用路径。

### 1. 已有缓存被启动任务再次下载

服务端日志第 558 行记录 11:04:52 已加载 57 个 JS/CSS 文件、6 个 source map、167 个字体文件。同一秒，第 564–567 行开始首次后台预热、全量更新，并重新下载已加载的 sweetalert2。快照中有 34 次资源刷新启动记录，其中 33 次已成功完成；这些资源均已在启动时从本地加载。NotoSansSC CSS 的处理又引发大量字体下载。

原因是首次后台任务调用 `update_all_cdn_files()` 时没有区分已有缓存和缺失缓存。该行为来自此前把首次预热移到后台的改动。

修复：首次任务调用 `update_all_cdn_files(missing_only=True)`，跳过已加载的非空缓存；缺失或空缓存继续在后台补齐。原有每小时全量更新与管理员主动刷新保留。缓存尚未就绪时的 `503 + Retry-After: 5` 行为保留。

### 2. 日志上传形成重复初始化循环

浏览器附件包含 16 次 `get_initial_data` 请求开始，其中 14 次带 `force: true`；请求约每 2 秒发出，前一个初始化尚未结束便继续发起。首个初始化出现约 30 秒超时。

源码中 `flushLogQueue()` 使用 `loadInitialData({frontend_logs, force: true})` 上传日志，业务初始化本身又输出新日志，形成反馈循环。这会读取业务数据、更新界面并增加后端负载，能够影响各类 WebUI 操作。

修复：日志批量上传改用已有的 `/api/log_frontend`，保留会话头、管理员查看来源头和 Cookie；最多允许一个在途批次。上传失败只通过原始 console 输出，不进入下一轮日志批次。客户端脱敏与服务端消息脱敏均保留。

### 3. 数据库访问被文件兼容接口放大

修复前请求完成记录如下：

| --- | ---: | ---: |

| `GET /api/site/bootstrap` | 6.91 秒 | 2030 |

登录请求在 11:06:33 输出“更新最后登录时间”后，同一请求到 11:08:15 才继续。该代码段包含保存登录资料和更新用户列表缓存。原缓存更新持有快照锁，并计算所有用户及学校账号绑定文件的签名；数据库兼容层的 `listdir` 和 `stat` 又会加载布局和业务表，将一次列表校验放大成许多远程 SQL 往返。

日志没有 SQL 分段耗时，不能断言全部 108 秒均来自数据库；代码路径和隔离测试确认了查询放大及锁竞争问题。

修复包括：

- 目录枚举只查询 registry 中的逻辑路径；不重建业务正文。
- 用户列表版本检查批量读取两个命名空间的 registry 元数据。
- 用户列表重建批量读取用户及绑定数据，保持账号归属和大小写隔离。
- 用独立刷新锁串行重建；数据库读取期间不持有短时快照锁。登录缓存更新不查询数据库。
- 用失效代数防止并发修改被旧快照覆盖；数据库直接更新业务列时仍通过定期刷新观察变更。
- 通用 `exists`、`isfile`、`stat` 保持原有读取和异常传播语义。

### 4. 配置读取额外写库

`get_frontend_config()` 原本在每次读取成功后调用 `_write_config_with_comments()`，目的是清理旧 INI 重复项。关系数据库模式下，这会把前端配置读取变成业务配置回写。

修复：移除读取路径中的自动回写，保留读取、配置默认值与地图上下文参数。配置保存入口继续负责写入。
